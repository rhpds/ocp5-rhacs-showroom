== What this workshop focuses on

One incident, then the controls that would have made the next one visible.

ACME Financial Services runs customer workloads on OpenShift. You are Sarah, a platform engineer. Morgan, from information security, pages you at 02:14 because a `payment-gateway` workload is sending unexpected traffic. You leave the pod running, find who opened the shell, cut off egress, and keep a forensic checkpoint. The next morning you roll a hardened image and lock Red Hat Advanced Cluster Security for Kubernetes (RHACS) process baselines.

The workshop stays on that arc:

* **Attribute the access.** The API audit log names the CI/CD service account that exec'd into the pod.
* **Contain without destroying evidence.** A deny-egress NetworkPolicy stops the outbound connection. The process stays up.
* **Capture volatile state.** A CRIU checkpoint records the process tree, including `exfil.sh`, without restarting the pod.
* **Shrink what a library bug can start.** CVE-2025-61765 is on the Socket.IO workload. You compare the images and roll a Red Hat Hardened Image with no shell.
* **Detect the next unexpected process.** An unlocked RHACS baseline only learns. A locked baseline raises *Unauthorized Process Execution*.

Plan on the *Terminal* tab, the OpenShift console, and RHACS. Credentials are on the xref:ROOT:index.adoc[roadshow home page].

== How to use this track

* Sign in from the xref:ROOT:index.adoc[roadshow home page]. This track does not use a separate registration app.
* Run commands in the *Terminal* tab. `oc` is already logged in after the home page setup script.
* Your namespaces are `payment-gateway-{workshop_user_suffix}` and `vulnerable-workload-{workshop_user_suffix}`.
* OpenShift GitOps syncs Application `security-response`, which creates those namespaces for suffix `1`.
* RHACS API calls use `ROX_CENTRAL_ADDRESS` and `ROX_API_TOKEN` from `~/.acs-roadshow/env`.

If those namespaces have no pods, sync Application `security-response` in OpenShift GitOps. For extra attendee suffixes, a cluster admin runs `./setup/deploy-incident-env.sh` from this repository. See `setup/README.adoc`.

When you finish, xref:ROOT:index.adoc[return to the roadshow home page].
