= VLAN Segmentation, MAC Spoof Filtering, and MultiNetworkPolicy
:role: Virtualization Network Security
:skills: NAD VLAN, MAC SpoofChk, MultiNetworkPolicy
:labid: LAB-VIRT-06
:toc:
:toclevels: 1
:icons: font

**Duration:** ~15 minutes

== Overview
xref:virt-05-storage-isolation.adoc[virt-05] isolated disks. This module isolates L2. The link:https://access.redhat.com/sites/default/files/attachments/rh-openshift-virtualization-hardening-guide-detail-202512-en.pdf[Red Hat OpenShift Virtualization hardening guide^] wants dedicated VLANs (Level 2), MAC spoof filtering (Level 1), and MultiNetworkPolicy microsegmentation inside a VLAN (Level 2, OVN-Kubernetes localnet).

Pod `NetworkPolicy` from xref:101-05-network-policy-basics.adoc[101-05] and cluster xref:301-03-multi-tenant-zero-trust-network.adoc[AdminNetworkPolicy] do not replace secondary-network policy on Multus/localnet. VMs on extra networks need NADs, spoof checking, and MultiNetworkPolicy.

== Why it matters
Two VMs on the same bridge see each other's broadcasts. MAC spoofing is a classic manipulator-in-the-middle on that segment. Without MultiNetworkPolicy, a VLAN is one flat trust zone.

== What does it solve

* All VMs on the default pod network with no L2 split
* SR-IOV or bridge ports with spoof check off
* A VLAN that is "isolated" but still allows every MAC on that VLAN to talk

== Your Mission
Inventory NetworkAttachmentDefinitions and SriovNetworks, then apply one OVN-Kubernetes localnet VLAN and one MultiNetworkPolicy in `rhacs-virt`. That pair is what a hardened VLAN looks like in the API. Do not attach the network to `rhel9-vm`, and do not create a node bridge mapping. This shared cluster has no physical VLAN 100.

=== Prerequisites

* xref:virt-05-storage-isolation.adoc[virt-05] complete
* OVN-Kubernetes is the usual default CNI; SR-IOV and bridge NADs are optional

Click each step for the full solution.

=== Control: Use dedicated VLANs to segment network traffic (Level 2 Control)

Put VM secondary interfaces on separate VLANs (OVN localnet `vlanID`, SR-IOV `spec.vlan`, or bridge CNI `vlan`) so guests are not on one L2 broadcast domain.

*Pros:* Broadcast and L2 attacks stay inside a VLAN. Tenants cannot ARP for each other unless you routed them.

*Cons / impact:* Services on other VLANs are unreachable without explicit routing or additional NICs. You must design which workloads share a VLAN.

*Default:* Dedicated VLANs are not configured. No VM has a VLAN until you create a NAD or SriovNetwork.

.Audit NAD and SR-IOV VLAN IDs
[%collapsible]
====
`spec.config` on a NetworkAttachmentDefinition is a *string* of JSON. Parse it.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get network-attachment-definitions.k8s.cni.cncf.io -A -o json | jq -r '
  ["NAMESPACE","NAME","TYPE","VLAN"],
  (.items[]
   | (.spec.config | if type == "string" then fromjson? // {} else . // {} end) as $c
   | [ .metadata.namespace,
       .metadata.name,
       ($c.type // "-"),
       (if $c.vlanID != null then ($c.vlanID | tostring)
        elif $c.vlan != null then ($c.vlan | tostring)
        else "-" end) ])
  | @tsv
' | column -t
----

[source,bash,subs="+macros,+attributes",role=execute]
----
echo '--- sriovnetwork vlan ---'
SRIOV_JSON="$(oc get sriovnetwork -A -o json 2>/dev/null)" || SRIOV_JSON=""
if [[ -z "${SRIOV_JSON}" ]]; then
  echo "No SriovNetwork CRD. A type=sriov row in the table above already shows that network's VLAN."
elif [[ "$(printf '%s' "${SRIOV_JSON}" | jq '.items | length')" == "0" ]]; then
  echo "No SriovNetworks."
else
  printf '%s' "${SRIOV_JSON}" | jq -r '
    .items[]
    | "\(.metadata.namespace)/\(.metadata.name)  vlan=\(.spec.vlan // "none")"
  '
fi
----

TIP: Read the table before you create anything. `openshift-ovn-kubernetes/default` is the cluster pod network (`VLAN` `-`). A dedicated VLAN is a number other than `0` or `-`. `0` means untagged. On this cluster, `mcp-demo-network/sriov-network` with VLAN `0` is the Level 2 gap. `rhacs-virt/vlan-100` is the example you add in the next step. If that row is already present, a previous run created it. Applying again is safe.
====

.Apply the hardened VLAN example
[%collapsible]
====
This creates the NetworkAttachmentDefinition the audit is looking for: OVN-Kubernetes localnet, VLAN 100, in the same project as `rhel9-vm`.

The object is only the record. It does not add a NIC to `rhel9-vm`, and it does not create a `NodeNetworkConfigurationPolicy`. A bridge mapping would touch the node network, which you do not do on this shared cluster.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: k8s.cni.cncf.io/v1
kind: NetworkAttachmentDefinition
metadata:
  name: vlan-100
  namespace: rhacs-virt
spec:
  config: |-
    {
      "cniVersion": "0.3.1",
      "name": "vlan-100",
      "type": "ovn-k8s-cni-overlay",
      "topology": "localnet",
      "netAttachDefName": "rhacs-virt/vlan-100",
      "vlanID": 100
    }
EOF
----

Run the VLAN table again. You want this row:

----
NAMESPACE                 NAME           TYPE                  VLAN
rhacs-virt                vlan-100       ovn-k8s-cni-overlay   100
----

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get network-attachment-definitions.k8s.cni.cncf.io -A -o json | jq -r '
  ["NAMESPACE","NAME","TYPE","VLAN"],
  (.items[]
   | (.spec.config | if type == "string" then fromjson? // {} else . // {} end) as $c
   | [ .metadata.namespace,
       .metadata.name,
       ($c.type // "-"),
       (if $c.vlanID != null then ($c.vlanID | tostring)
        elif $c.vlan != null then ($c.vlan | tostring)
        else "-" end) ])
  | @tsv
' | column -t
----

The other rows stay. `100` is the hardened VLAN. `-` on the pod network and `0` on `sriov-network` are unchanged.

OVN localnet filters spoofed MACs by default, so this JSON has no `macspoofchk` key. Bridge CNI would set `"vlan": 100`, `"preserveDefaultVlan": false`, and `"macspoofchk": true`. SR-IOV would set `spec.vlan: 100` and `spec.spoofChk: on` on a `SriovNetwork`. This cluster has no `SriovNetwork` CRD.

Docs: link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/virtualization/virt-connecting-a-virtual-machine-to-a-linux-bridge[VLAN with bridge CNI^], link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/virtualization/virt-connecting-a-virtual-machine-to-an-ovn-kubernetes-secondary-network[OVN localnet^], link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/networking/hardware-networks#nw-sriov-network-attachment_configuring-sriov-net-attach[SR-IOV networks^].

TIP: Leave `rhel9-vm` on the pod network. The next control checks spoof filtering, then you add the MultiNetworkPolicy that names this NAD.

=== Control: Enable MAC spoof filtering (Level 1 Control)

Spoof checking drops frames whose source MAC is not the MAC allocated to that VM port.

*Pros:* A compromised guest cannot impersonate another MAC on the segment (manipulator-in-the-middle, some DHCP/ARP tricks).

*Cons / impact:* None for ordinary guests. Workloads that *must* use additional MACs (some clustered NICs, MACVLAN inside the guest) need a documented exception.

*Default:* OVN-Kubernetes localnet enables MAC spoof filtering. Bridge and SR-IOV must be turned on in the NAD or SriovNetwork.

.Audit spoof check
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
echo '=== SR-IOV spoofChk ==='
SRIOV_JSON="$(oc get sriovnetwork -A -o json 2>/dev/null)" || SRIOV_JSON=""
if [[ -z "${SRIOV_JSON}" ]]; then
  echo "No SriovNetwork CRD, so there is no spec.spoofChk to read."
  echo "A type=sriov row is judged from its NetworkAttachmentDefinition spoofchk field below."
elif [[ "$(printf '%s' "${SRIOV_JSON}" | jq '.items | length')" == "0" ]]; then
  echo "No SriovNetworks."
else
  printf '%s' "${SRIOV_JSON}" | jq -r '
    .items[]
    | (.spec.spoofChk // "omitted") as $s
    | if $s == "off" then
        "\(.metadata.namespace)/\(.metadata.name)  gap: spoofChk is off."
      elif $s == "on" then
        "\(.metadata.namespace)/\(.metadata.name)  pass: spoofChk is on."
      else
        "\(.metadata.namespace)/\(.metadata.name)  pass: spoofChk is omitted. The SR-IOV default is on."
      end
  '
fi
----

[source,bash,subs="+macros,+attributes",role=execute]
----
echo '=== NAD spoof check ==='
NAD_JSON="$(oc get network-attachment-definitions.k8s.cni.cncf.io -A -o json 2>/dev/null)" || NAD_JSON=""
if [[ -z "${NAD_JSON}" ]]; then
  echo "NetworkAttachmentDefinition CRD is not installed. No secondary networks to audit."
elif [[ "$(printf '%s' "${NAD_JSON}" | jq '.items | length')" == "0" ]]; then
  echo "No NetworkAttachmentDefinitions."
else
  printf '%s' "${NAD_JSON}" | jq -r '
    .items[]
    | . as $item
    | (.spec.config | if type == "string" then fromjson? // {} else . // {} end) as $c
    | ($item.metadata.namespace + "/" + $item.metadata.name) as $id
    | if $id == "openshift-ovn-kubernetes/default" then
        "\($id)  skip: cluster pod network. An unset macspoofchk here is not this control."
      elif $c.type == "bridge" then
        if $c.macspoofchk == true then
          "\($id)  pass: bridge macspoofchk is true."
        else
          "\($id)  gap: bridge macspoofchk must be true. Found \(if $c.macspoofchk == null then "unset" else ($c.macspoofchk | tostring) end). Bridge defaults to false when the key is missing."
        end
      elif $c.type == "sriov" then
        ($c.spoofchk // $c.spoofChk // "omitted") as $s
        | if ($s == "off" or $s == false) then
            "\($id)  gap: SR-IOV spoofchk is off."
          elif ($s == "on" or $s == true) then
            "\($id)  pass: SR-IOV spoofchk is on."
          else
            "\($id)  pass: spoofchk is omitted, so the SR-IOV plugin keeps spoof checking on. macspoofchk is a bridge field and stays unset on this network."
          end
      elif ($c.type == "ovn-k8s-cni-overlay" and $c.topology == "localnet") then
        "\($id)  pass: OVN localnet filters spoofed MACs by default. A missing macspoofchk key is expected."
      elif $c.type == "ovn-k8s-cni-overlay" then
        "\($id)  skip: OVN overlay, not a localnet VLAN."
      else
        "\($id)  review: type=\($c.type // "unknown"). Check that provider spoof field."
      end
  '
fi
----

After you apply the VLAN example, expect lines like these:

----
No SriovNetwork CRD, so there is no spec.spoofChk to read.
A type=sriov row is judged from its NetworkAttachmentDefinition spoofchk field below.
=== NAD spoof check ===
mcp-demo-network/sriov-network  pass: spoofchk is omitted, so the SR-IOV plugin keeps spoof checking on. macspoofchk is a bridge field and stays unset on this network.
openshift-ovn-kubernetes/default  skip: cluster pod network. An unset macspoofchk here is not this control.
rhacs-virt/vlan-100  pass: OVN localnet filters spoofed MACs by default. A missing macspoofchk key is expected.
----

`rhacs-virt/vlan-100` appears only after you applied the example. A line that starts with `gap:` is the only finding. `unset` by itself is not a finding.

TIP: Fix a `gap:` row in the NAD or SriovNetwork for that provider. Re-run this command after the change. Existing VM attachments may need a restart to pick up CNI config.
====

.Remediation
[%collapsible]
====
Enable spoof check only where the audit printed `gap:`.

Bridge NAD: set `"macspoofchk": true`. SR-IOV: set `"spoofchk": "on"` in the NAD, or `spec.spoofChk: on` on the `SriovNetwork`. Leave OVN localnet unchanged. It already filters spoofed MACs.

See link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/networking/hardware-networks[SR-IOV CNI^] and the bridge CNI NAD `macspoofchk` field in link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/networking/multiple-networks[multiple networks^].
====

=== Control: Use MultiNetworkPolicy (Level 2 Control)

MultiNetworkPolicy selects a VM *and* the NetworkAttachmentDefinition it uses, then allows only listed ingress/egress on that secondary network. After the first policy in a namespace matches a VM+NAD pair, everything else on that network is denied.

*Pros:* Microsegmentation inside a VLAN. East-west is explicit.

*Cons / impact:* A partial policy can isolate a VM from DNS, backup, or its application peers. You must allow what you still need. Feature is tied to OVN-Kubernetes localnet.

*Default:* `useMultiNetworkPolicy` is false. The `MultiNetworkPolicy` kind is not registered, so apply fails with `no matches for kind "MultiNetworkPolicy" in version "k8s.cni.cncf.io/v1beta1"`.

.Audit MultiNetworkPolicy
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
if oc get crd multi-networkpolicies.k8s.cni.cncf.io >/dev/null 2>&1; then
  echo "MultiNetworkPolicy CRD is installed."
  oc get multi-networkpolicy -A
  echo "An empty list means the feature is on and allow-same-vlan does not exist yet."
else
  echo "MultiNetworkPolicy CRD is not installed."
  echo "oc apply fails with: no matches for kind \"MultiNetworkPolicy\" in version \"k8s.cni.cncf.io/v1beta1\"."
  echo "That is the default. The next step sets useMultiNetworkPolicy: true, which installs this API."
fi
----

TIP: `rhel9-vm` is on the pod network, so NetworkPolicy and AdminNetworkPolicy cover it. This CR covers a secondary network only. Enable the API, then create `allow-same-vlan` on `vlan-100`.
====

.Enable the MultiNetworkPolicy API
[%collapsible]
====
The YAML you apply is already `k8s.cni.cncf.io/v1beta1`. The cluster has not installed that CRD. The Cluster Network Operator installs it when `spec.useMultiNetworkPolicy` is true, and starts the nftables policy pods in `openshift-multus`. This does not change the pod network.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc patch network.operator.openshift.io cluster --type=merge --patch '{"spec":{"useMultiNetworkPolicy":true}}'
echo "Waiting for the MultiNetworkPolicy CRD..."
for i in $(seq 1 36); do
  if oc get crd multi-networkpolicies.k8s.cni.cncf.io >/dev/null 2>&1; then
    echo "MultiNetworkPolicy CRD is installed."
    break
  fi
  sleep 5
done
oc get crd multi-networkpolicies.k8s.cni.cncf.io
----

`network.operator.openshift.io/cluster patched` is the patch. The CRD line must show `multi-networkpolicies.k8s.cni.cncf.io`. Patching again is safe if a previous run already set the flag. If the CRD is still missing after the wait, check `oc get clusteroperators network` before you apply the policy.

Docs: link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/networking/multiple-networks#nw-multus-multi-network-policy[Enable multi-network policy^].
====

.Apply the policy for vlan-100
[%collapsible]
====
Run this after `rhacs-virt/vlan-100` exists and the CRD command above succeeds. The annotation `k8s.v1.cni.cncf.io/policy-for` binds the policy to that NAD. The allow rule is an `ipBlock`, which is the selector OpenShift Virtualization supports on a secondary network. A `podSelector` inside `from:` does not select VM peers unless the NAD also sets `subnets`.

`10.100.100.0/24` is the example allow list for this VLAN. It is not the cluster pod network. No VM is attached to `vlan-100`, so this does not filter `rhel9-vm`. After the first policy matches a VM and this NAD, every other flow on that network is denied. That deny stays harmless until you attach a guest.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: k8s.cni.cncf.io/v1beta1
kind: MultiNetworkPolicy
metadata:
  name: allow-same-vlan
  namespace: rhacs-virt
  annotations:
    k8s.v1.cni.cncf.io/policy-for: rhacs-virt/vlan-100
spec:
  podSelector: {}
  policyTypes:
    - Ingress
  ingress:
    - from:
        - ipBlock:
            cidr: 10.100.100.0/24
EOF
----

Confirm the policy points at the VLAN:

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get multi-networkpolicy -n rhacs-virt allow-same-vlan -o jsonpath='{.metadata.annotations.k8s\.v1\.cni\.cncf\.io/policy-for}{"\n"}'
----

----
rhacs-virt/vlan-100
----

That one line is the hardened VLAN: secondary network `vlan-100` in `rhacs-virt`, plus a policy that allows only `10.100.100.0/24` on it. `oc get multi-networkpolicy -A` now lists `allow-same-vlan`. Applying again updates the same object.

See link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/networking/multiple-networks#nw-multus-multi-network-policy[MultiNetworkPolicy^].

TIP: Do not add a secondary interface to `rhel9-vm`. The audit can see the hardened shape without moving the lab guest.
====

== Debrief

L2 first (`rhacs-virt/vlan-100`), then spoof check on the port (on by default for that OVN localnet), then `allow-same-vlan` inside the VLAN. Pod NetworkPolicy remains for the primary CNI (xref:101-05-network-policy-basics.adoc[101-05], xref:301-03-multi-tenant-zero-trust-network.adoc[301-03]).

What breaks without this:

* Flat L2 between VMs
* Forged MACs on a bridge
* A VLAN that is one big allow-any
