= 6.1 GitOps + Admission
:source-highlighter: rouge
:toc:
:toclevels: 1

== Overview

You promote the signed app digest into *stage* via GitOps, then turn on admission so unsigned images cannot run. You edit *one* file on the *stage* Gitea remote. That file is `admission/trust-policy.yaml` (`kind: TrustPolicy`). A CronJob renders namespaced `ImagePolicy` on `lw-poc-staging` *and* `lw-poc-prod`. Do not apply `ClusterImagePolicy`. Do not use RHACS Trusted image signers for this gate.

Native `ImagePolicy` `signedEmail` must be an email. Track 5.1 identity is a Kubernetes service-account URI, so the CronJob renders `policyType: PublicKey` from ConfigMap `lab-cosign-pubkey` (the 5.3 `cosign.pub` you published). Keep the 5.1 service-account URI in TrustPolicy. That is still the Fulcio identity. `oc tag` does not copy `.sig` tags. Use `cosign copy` (and a dest-repo `cosign sign --key`) after the tag.

Prod GitOps is a *second remote*. Leave it for xref:tssc-16-prod-gitops.adoc[6.2]. `app-operate` NetworkPolicy on staging stays *open*. That is not the xref:tssc-10-build-networkpolicy.adoc[4.3] build-egress lab.

== Why it matters

Only the signed digest may run. Lightwell pins inside the image do not admit an unsigned tag. Unsigned deny is a *pull* failure (`ImagePullBackOff`), not `oc apply` stderr.

You fill TrustPolicy (`enforce: true`, live digest, pipeline service-account subject) and run `cosign copy` after `oc tag` because signatures do not travel with `oc tag` by themselves. Prod Argo stays on the prod remote.

Lightwell Network and Clearinghouse Premier are already in the image as GAVs. Admission does not inspect Maven. A Premier member version does not skip unsigned deny.

== What does it solve

* Unsigned images that still deploy
* Signatures that are not copied after `oc tag`
* Using `ClusterImagePolicy` instead of namespaced `ImagePolicy`
* Mixing stage and prod remotes

== Your change: tag, stage GitOps, TrustPolicy

. Copy the RHTAS TUF Fulcio CA and Rekor public key into Secret `tssc-admission/rhtas-tuf-keys`. The admission CronJob reads those keys. Skip this when `fulcio_v1.crt.pem` is already present.
+
[source,bash,role=execute]
----
if oc -n tssc-admission get secret rhtas-tuf-keys -o jsonpath='{.data.fulcio_v1\.crt\.pem}' 2>/dev/null | grep -q .; then
  echo "rhtas-tuf-keys already has the Fulcio CA"
else
  TUF_HOST="$(oc -n trusted-artifact-signer get route -o jsonpath='{range .items[*]}{.spec.to.name}{"\t"}{.spec.host}{"\n"}{end}' \
    | awk -F '\t' '$1=="tuf"{print $2; exit}')"
  test -n "${TUF_HOST}"
  mkdir -p /tmp/tuf-keys
  fetch_by_suffix() {
    local dest="$1" suffix="$2" href=""
    href="$(curl -fsSk --max-time 20 "https://${TUF_HOST}/targets/" \
      | grep -oE "href=\"[^\"]*${suffix}\"" | head -1 | sed 's/^href="//;s/"$//')" || true
    [[ -n "${href}" ]] && curl -fsSk --max-time 20 -o "${dest}" "https://${TUF_HOST}/targets/${href}"
  }
  if ! fetch_by_suffix /tmp/tuf-keys/fulcio_v1.crt.pem fulcio_v1.crt.pem \
    || ! fetch_by_suffix /tmp/tuf-keys/rekor.pub rekor.pub; then
    python3 - <<'PY'
import base64, json, os, subprocess
names = subprocess.check_output(
    ["oc", "-n", "trusted-artifact-signer", "get", "secret", "-o", "jsonpath={.items[*].metadata.name}"],
    text=True,
).split()
fulcio = rekor = None
for name in names:
    raw = subprocess.check_output(
        ["oc", "-n", "trusted-artifact-signer", "get", "secret", name, "-o", "json"],
        text=True,
    )
    for value in (json.loads(raw).get("data") or {}).values():
        text = base64.b64decode(value).decode("utf-8", "replace")
        if "BEGIN CERTIFICATE" in text and fulcio is None:
            fulcio = text
        if ("BEGIN PUBLIC KEY" in text or "BEGIN REKOR" in text) and rekor is None and "BEGIN CERTIFICATE" not in text:
            rekor = text
if not fulcio or not rekor:
    raise SystemExit("Could not find Fulcio CA and Rekor public key from the TUF route or Secrets")
os.makedirs("/tmp/tuf-keys", exist_ok=True)
open("/tmp/tuf-keys/fulcio_v1.crt.pem", "w").write(fulcio if fulcio.endswith("\n") else fulcio + "\n")
open("/tmp/tuf-keys/rekor.pub", "w").write(rekor if rekor.endswith("\n") else rekor + "\n")
print("Wrote PEMs from Secret scan")
PY
  fi
  test -s /tmp/tuf-keys/fulcio_v1.crt.pem && test -s /tmp/tuf-keys/rekor.pub
  oc -n tssc-admission create secret generic rhtas-tuf-keys \
    --from-file=fulcio_v1.crt.pem=/tmp/tuf-keys/fulcio_v1.crt.pem \
    --from-file=rekor.pub=/tmp/tuf-keys/rekor.pub \
    --dry-run=client -o yaml | oc apply -f -
  echo "Wrote tssc-admission/rhtas-tuf-keys"
fi
oc -n tssc-admission annotate secret rhtas-tuf-keys argocd.argoproj.io/tracking-id- --overwrite || true
oc -n tssc-admission label secret rhtas-tuf-keys app.kubernetes.io/instance- --overwrite || true
----

Expected output:

----
secret/rhtas-tuf-keys created
Wrote tssc-admission/rhtas-tuf-keys

. Tag the signed image into staging (not prod). `oc tag` copies the image, not `.sig` tags. The bastion cannot reach the internal registry, so `cosign copy` and `cosign sign` run in a short-lived pod in `default`, the same way as xref:tssc-14-disconnected-verify.adoc[5.3]. Grant the staging `builder` service account `system:image-puller` on the build namespace so that pod can read the source digest and push the staging repo. Sign the dest repo with the 5.3 key. `-f` overwrites an existing signature tag so you can run the step again.
+
[source,bash,role=execute]
----

PROMOTE_NS="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_promote_namespace}')"
oc policy add-role-to-user system:image-puller \
  "system:serviceaccount:${PROMOTE_NS}:builder" -n "${BUILD_NS}"
oc tag "${BUILD_NS}/spring-boot-lw-poc:latest" "${PROMOTE_NS}/spring-boot-lw-poc:latest"
DIGEST="$(oc -n "${PROMOTE_NS}" get istag spring-boot-lw-poc:latest \

== Key takeaways

* Admission is namespaced `ImagePolicy` from one TrustPolicy file you own. It is not `ClusterImagePolicy`.
* Lightwell Network and Clearinghouse Premier GAVs do not bypass unsigned deny.
* Service-account URI subjects render `PublicKey` from 5.3 `lab-cosign-pubkey`. `oc tag` needs `cosign copy`.
* Promotion to prod is a git commit to a second remote (6.2).
