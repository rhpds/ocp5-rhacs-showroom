= 3.3 Live Renovate
:source-highlighter: rouge
:toc:
:toclevels: 1

== Overview

Merge a real `renovate-bot` pull request that updates stale `lightwell-pins.properties` on `lw-student/spring-boot-lw-poc`. A hand-edited commit fails this Check. Copying the worked example fails too.

MintMaker is the hosted Konflux name for this bot. This cluster does not install hosted Konflux. It uses an in-cluster CronJob. The term map is in xref:appendix-konflux-mapping.adoc[Konflux Mapping].

== Why it matters

Pin refresh cannot depend on a human noticing a new Lightwell version. Remediations arrive as pull requests against your git. You review and merge them. A student-authored commit on the pins file is not that control.

Lightwell Network catalog bumps (`.rhlw-00000` to `.rhlw-00001`, dest Hummingbird digest) are what this bot is seeded to see. Clearinghouse Premier member-specific versions would appear the same way once Nexus has metadata the bot can read. During a Premier embargo, merge the pin. Do not paste the CVE or advisory text into a public PR description.

== What does it solve

* Manual pin edits that drift
* Student-authored commits pretending to be the bot
* Pasting advisory text into a public PR during embargo

== Why a bot PR

Renovate (or MintMaker on hosted Konflux) opens PRs against your git when a vetted version exists. Here the git is Gitea. Do not use `github.com` for this Check.

Stale seed (do not “fix” these yourself). The bot opens *one* grouped PR that moves *both* lines:

* `commons-lang3=3.14.0.rhlw-00000` → remediated `3.14.0.rhlw-00001` in Nexus
* `hummingbird-digest` all-zero → dest digest after 1.2

Merging only the Maven bump used to leave a second digest PR unmergeable on the same file. Do not hand-edit the leftover line.

The CronJob retries about every 20 minutes.

== Your change: merge the renovate-bot PR

. GitOps leaves Secret `renovate/renovate-gitea-token` as `REPLACE_ME`. Create the `renovate-bot` user and token from the Gitea admin secret, then start one CronJob run. Re-running this is safe when the token is already set.
+
[source,bash,role=execute]
----
GITEA_URL="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')"
ORG="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_gitea_org}')"
REPO="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_name}')"
ADMIN_USER="$(oc -n gitea get secret gitea-admin -o jsonpath='{.data.username}' | base64 -d)"
ADMIN_PASS="$(oc -n gitea get secret gitea-admin -o jsonpath='{.data.password}' | base64 -d)"
API="${GITEA_URL%/}/api/v1"
CURRENT="$(oc -n renovate get secret renovate-gitea-token -o jsonpath='{.data.token}' 2>/dev/null | base64 -d || true)"
if [[ -z "${CURRENT}" || "${CURRENT}" == "REPLACE_ME" ]]; then
  BOT_PASSWORD='workshop-renovate-bot-changeme'
  CREATE_CODE="$(curl -sk -o /tmp/renovate-bot-create.json -w '%{http_code}' \
    -u "${ADMIN_USER}:${ADMIN_PASS}" -H 'Content-Type: application/json' \
    -d "{\"username\":\"renovate-bot\",\"email\":\"renovate-bot@workshop.local\",\"full_name\":\"Renovate Bot\",\"password\":\"${BOT_PASSWORD}\",\"must_change_password\":false,\"send_notify\":false}" \
    -X POST "${API}/admin/users")"
  echo "create user HTTP ${CREATE_CODE}"
  LIST_CODE="$(curl -sk -o /tmp/renovate-tokens.json -w '%{http_code}' \
    -u "renovate-bot:${BOT_PASSWORD}" "${API}/users/renovate-bot/tokens")"
  if [[ "${LIST_CODE}" == "200" ]]; then
    python3 -c 'import json
tokens=json.load(open("/tmp/renovate-tokens.json"))
open("/tmp/renovate-token-ids","w").write("\n".join(str(t["id"]) for t in tokens if t.get("name")=="renovate"))'
    while IFS= read -r id; do
      [[ -z "${id}" ]] && continue
      curl -sk -o /dev/null -X DELETE -u "renovate-bot:${BOT_PASSWORD}" \
        "${API}/users/renovate-bot/tokens/${id}"
    done < /tmp/renovate-token-ids
  fi
  TOKEN_CODE="$(curl -sk -o /tmp/renovate-token.json -w '%{http_code}' \
    -u "renovate-bot:${BOT_PASSWORD}" -H 'Content-Type: application/json' \
    -d '{"name":"renovate","scopes":["write:repository","write:issue","read:user","write:notification"]}' \
    -X POST "${API}/users/renovate-bot/tokens")"
  if [[ "${TOKEN_CODE}" != "201" ]]; then
    TOKEN_CODE="$(curl -sk -o /tmp/renovate-token.json -w '%{http_code}' \
      -u "renovate-bot:${BOT_PASSWORD}" -H 'Content-Type: application/json' \
      -d '{"name":"renovate","scopes":["all"]}' \
      -X POST "${API}/users/renovate-bot/tokens")"
  fi
  echo "create token HTTP ${TOKEN_CODE}"
  TOKEN="$(python3 -c 'import json; print(json.load(open("/tmp/renovate-token.json")).get("sha1") or "")')"
  test -n "${TOKEN}"
  oc -n renovate patch secret renovate-gitea-token --type merge \
    -p "{\"stringData\":{\"token\":\"${TOKEN}\"}}"
  rm -f /tmp/renovate-token.json
  echo "Stored renovate-gitea-token"
else
  echo "renovate-gitea-token already set"
fi
curl -sk -o /dev/null -w "collaborator HTTP %{http_code}\n" -X PUT \
  -u "${ADMIN_USER}:${ADMIN_PASS}" -H 'Content-Type: application/json' \
  -d '{"permission":"write"}' \
  "${API}/repos/${ORG}/${REPO}/collaborators/renovate-bot"
oc -n renovate delete job renovate-now --ignore-not-found
oc -n renovate create job renovate-now --from=cronjob/renovate
----
+
When the token is already stored, the script skips user creation.
+
Expected output:
+
----
renovate-gitea-token already set
collaborator HTTP 204
job.batch/renovate-now created
----

. In Gitea, open `lw-student/spring-boot-lw-poc` → *Pull Requests*.
. The scored PR author is `renovate-bot`. Files must include `lightwell-pins.properties`. Both seed values (`rhlw-00000` and the all-zero digest) should move in that one PR.
. Review, then merge on Gitea (do not `git commit` the same hunk as `student`).

== Check: merged commit is the bot

Pass when:

* Latest merge (or the merge commit) author is `renovate-bot`, not `student`
* `lightwell-pins.properties` moved off `rhlw-00000` / all-zero digest
* You did not recreate that diff as a hand commit

Honor system: Track 4 still opens. A seeded or student-authored pin bump still fails this lab.

== Callout: pip pins

Renovate on a PyPI app watches `requirements.txt` (or `pyproject.toml`) for `+rhlw.*` bumps the same way this Check watches `lightwell-pins.properties`. This Check is the Maven pins file on Gitea.

== Callout: Artifactory datasources

In many organizations, Renovate (or MintMaker) often reads Maven metadata from Artifactory remotes or virtuals instead of in-cluster Nexus. The Check is still a `renovate-bot` PR on Gitea against this cluster’s Nexus.
