= Feature Gates and Trusted HyperConverged Config
:role: Virtualization Platform Hardening
:skills: HCO Feature Gates, Insecure Registries, jsonpatch Annotations
:labid: LAB-VIRT-01
:toc:
:toclevels: 1

**Duration:** ~25 minutes

== Overview
xref:virt-00-scope-and-hco.adoc[virt-00] found `HyperConverged/kubevirt-hyperconverged`. This module scores the *least functionality* controls on that object: 

* non-root virt-launcher
* persistent SCSI reservations
* downward metrics into the guest
* TLS-only registries for CDI imports
* and the jsonpatch annotations that bypass HCO.

Most of these are already at the secure default. Your job is to prove it and know the patch you would apply if an audit ever fails.

== Why it matters
Feature gates and annotations are how a platform team quietly reintroduces over privileged helpers, host metrics in the guest, or experimental patches that are not supported. 

*Auditors will ask what is enabled on HCO, not whether the VM "looks fine."*

== What does it solve

* Enabling Root virt-launcher on clusters
* Persistent reservations left on when no Windows Shared Cluster Filesystem exists
* Host/VM performance data exposed to guests
* CDI pulling disk images over HTTP from unknown registries
* jsonpatch annotations that mutate KubeVirt, CDI, network add-ons, or SSP outside HCO

== Your Mission
Audit five HCO controls. Leave the live object at the secure default. Use the remediation blocks only if an audit already fails.

The `kubevirt` jsonpatch annotation is the one expected exception. The last control explains why it is set, and why you leave it.

=== Prerequisites

* xref:virt-00-scope-and-hco.adoc[virt-00] complete (`HyperConverged` exists)

Click each step for the full solution.

=== Control: Enable nonRoot (pre-4.18)

The `nonRoot` feature gate makes virt-launcher run without root. From OpenShift Virtualization 4.18 the field is ignored and non-root is always on.

*Pros:* Removes a classic container-to-host escalation path; matches OpenShift's non-root default for pods.

*Cons / impact:* Anything that still assumed root in the launcher breaks. You need a supported identification path for remaining admin tasks.

*Default:* Non-root is the KubeVirt default. From 4.18 the gate is deprecated and always enabled.

.Audit nonRoot
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv \
  -o jsonpath='nonRoot={.spec.featureGates.nonRoot}{"\n"}'
oc get csv -n openshift-cnv -o custom-columns=NAME:.metadata.name,VERSION:.spec.version --no-headers \
  | grep '^kubevirt-hyperconverged-operator'
----

TIP: `nonRoot=true` is the pass on pre-4.18. On 4.18+ `nonRoot=` may be empty. Operator version 4.18 or later means non-root is already enforced, so skip the patch. Ignore other CSVs in this namespace.
====

.Remediation (pre-4.18 only)
[%collapsible]
====
Skip this patch on 4.18+. On older clusters set the gate to `true`:

[source,bash,subs="+macros,+attributes",role=execute]
----
oc patch hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv --type='json' -p='[
  {"op": "replace", "path": "/spec/featureGates/nonRoot", "value": true}
]'
----

TIP: Re-run the audit. Output should be `true`.
====

=== Control: Disable persistentReservation

Persistent SCSI reservations share a LUN among VMs. They exist for Windows Shared Cluster Filesystem and pull in `qemu-pr-helper` with extra privilege.

*Pros:* Least functionality; no privileged helper unless that Windows clustered-disk use case is real.

*Cons / impact:* Those clustered Windows filesystems cannot reserve the LUN. Leave the gate off unless that workload is an explicit exception.

*Default:* Disabled (`false`).

.Audit persistentReservation
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv \
  -o jsonpath='{.spec.featureGates.persistentReservation}{"\n"}'
----

TIP: `false` or empty is a pass. Do not enable this gate to "see what happens" on a shared cluster.
====

.Remediation
[%collapsible]
====
Only if the audit returned `true` and you do not run Windows Shared Cluster Filesystem:

[source,bash,subs="+macros,+attributes",role=execute]
----
oc patch hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv --type='json' -p='[
  {"op": "replace", "path": "/spec/featureGates/persistentReservation", "value": false}
]'
----

TIP: Audit should return `false`.
====

=== Control: Disable downwardMetrics

`downwardMetrics` exposes extra host and VM performance data to the guest.

*Pros:* Shrinks reconnaissance data a compromised guest can read about the node.

*Cons / impact:* Guests cannot consume those host metrics. Use Prometheus on the cluster (virt-07 vCPU metrics) instead of leaking them into the VM.

*Default:* `false`.

.Audit downwardMetrics
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv \
  -o jsonpath='{.spec.featureGates.downwardMetrics}{"\n"}'
----

TIP: `false` or empty is a pass.
====

.Remediation
[%collapsible]
====
Only if the audit returned `true`:

[source,bash,subs="+macros,+attributes",role=execute]
----
oc patch hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv --type='json' -p='[
  {"op": "replace", "path": "/spec/featureGates/downwardMetrics", "value": false}
]'
----

TIP: Audit should return `false`.
====

=== Control: Enforce trusted registries using TLS

`spec.storageImport.insecureRegistries` is the allow-list of registries CDI may contact *without* TLS. Empty means TLS-only trusted registries.

*Pros:* Disk images and container sources are not imported over cleartext or from unknown HTTP endpoints.

*Cons / impact:* Air-gapped or lab registries that only speak HTTP will fail until you put TLS in front of them (or accept a documented exception).

*Default:* No insecure registries. The jsonpath should be empty.

.Audit insecureRegistries
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv \
  -o jsonpath='{.spec.storageImport.insecureRegistries}{"\n"}'
----

TIP: Empty output is a pass. Any hostname listed is a finding.
====

.Remediation
[%collapsible]
====
Remove the entire allow-list (only if it is populated and you intend to break those HTTP imports):

[source,bash,subs="+macros,+attributes",role=execute]
----
oc patch hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv --type='json' -p='[
  {"op": "remove", "path": "/spec/storageImport/insecureRegistries"}
]'
----

TIP: Re-run the audit. It should print nothing.
====

=== Control: Restrict HCO jsonpatch annotations

HCO honors experimental jsonpatch annotations on itself: `kubevirt.kubevirt.io/jsonpatch`, `containerizeddataimporter.kubevirt.io/jsonpatch`, `networkaddonsconfigs.kubevirt.io/jsonpatch`, and `ssp.kubevirt.io/jsonpatch`. Those patches mutate child operands outside the supported HCO spec. HCO reapplies the patch on every reconcile, so an annotation can quietly undo a security field you set in `spec`.

A hardened cluster has none of these keys. That is still the guide.

This roadshow sets one key, `kubevirt.kubevirt.io/jsonpatch`, so RHACS can scan the guest. Sensor pulls the `roxagent` package report over VSOCK, through the KubeVirt API. That inventory has no path over the guest IP address. VSOCK is still a KubeVirt feature gate. OpenShift Virtualization 4.22 did not add it to `spec.featureGates` and did not turn the annotation on by itself. Job `enable-vsock` in the `rhacs-virt` GitOps app writes the annotation. The patch body is a single add of `VSOCK`.

The gate makes the device available. A virtual machine receives it when `spec.domain.devices.autoattachVSOCK` is `true`. `rhel9-vm` sets that so ACS can scan it. Sensor still needs RBAC to `GET` `virtualmachineinstances/vsock`. The socket stays on the hypervisor. The CDI, network, and SSP annotations stay unset.

*Pros:* Administrators configure Virtualization through HCO fields. An arbitrary jsonpatch can disable security defaults on every reconcile.

*Cons / impact:* A setting that exists only as a jsonpatch is unsupported. VSOCK is the documented exception on this cluster, because RHACS VM scanning requires it.

*Default:* None of the annotations are set. `jq has(...)` returns `false`.

*This cluster:* `kubevirt` is `true`. Read the value and confirm it only adds `VSOCK`. Leave that annotation. `cdi`, `network`, and `ssp` stay `false`.

.Audit jsonpatch annotations
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv -o json | jq '
  .metadata.annotations // {}
  | {
      kubevirt: has("kubevirt.kubevirt.io/jsonpatch"),
      cdi: has("containerizeddataimporter.kubevirt.io/jsonpatch"),
      network: has("networkaddonsconfigs.kubevirt.io/jsonpatch"),
      ssp: has("ssp.kubevirt.io/jsonpatch")
    }
'
oc get hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged -n openshift-cnv \
  -o jsonpath='{.metadata.annotations.kubevirt\.kubevirt\.io/jsonpatch}{"\n"}'
----

TIP: `cdi`, `network`, and `ssp` are `false`. `kubevirt` is `true`. The printed patch is the VSOCK add: `[{"op":"add","path":"/spec/configuration/developerConfiguration/featureGates/-","value":"VSOCK"}]`. Any other operation in that string is a finding.
====

.Remediation
[%collapsible]
====
Leave the VSOCK annotation in place. It is what lets Sensor collect guest package inventory for the RHACS VM exercise. Removing it stops that collection. The next sync of `rhacs-virt` writes the same annotation again.

Remove a key only when it is unexpected. That means `cdi`, `network`, or `ssp` is `true`. The trailing `-` removes that annotation. This command leaves the VSOCK key alone:

[source,bash,subs="+macros,+attributes"]
----
oc annotate --overwrite -n openshift-cnv hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged \
  'containerizeddataimporter.kubevirt.io/jsonpatch-' \
  'networkaddonsconfigs.kubevirt.io/jsonpatch-' \
  'ssp.kubevirt.io/jsonpatch-'
----

If the kubevirt value contains anything besides the VSOCK add, clear it and tell an instructor. `rhacs-virt` will restore the VSOCK add on the next sync:

[source,bash,subs="+macros,+attributes"]
----
oc annotate --overwrite -n openshift-cnv hyperconvergeds.v1beta1.hco.kubevirt.io kubevirt-hyperconverged \
  'kubevirt.kubevirt.io/jsonpatch-'
----

TIP: Re-run the audit. `kubevirt` stays `true` with the VSOCK add. The other three stay `false`.
====

== Debrief

HCO is the supported control plane for these five settings. Empty/false is the hardened baseline. Do not turn gates on just to demonstrate a patch.

The kubevirt jsonpatch on this cluster is the VSOCK exception for RHACS. The guide still says that annotation should be absent. Here it is present so Sensor can pull `roxagent` reports, and the patch does nothing besides enable that gate. Leave it.

What breaks without this:

* `qemu-pr-helper` and clustered SCSI reservations you do not need
* Guest-visible host metrics
* HTTP registry imports of VM disks
* A jsonpatch that changes HCO security fields on every reconcile
* Removing the VSOCK annotation, which stops ACS from refreshing guest package inventory
